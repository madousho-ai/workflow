# plan-arch

本 Skill 定义一系列跟用户探讨，目的对齐，最后给出完整方案的流程

## When to use

以下任意情况触发:
- 用户想进行大范围更改，横跨多个代码模块
- 用户试图创建新的功能模块 (ex. 实现协议库/新事务)
- 在项目早期规划阶段

## Definition

### 用户状态机
有以下状态/事件:
- 新需求
- 需求共识
- 架构研究
- 架构共识

#### 状态切换

##### 新需求  
当用户提出一个新的需求(跨出当前讨论主题)时切换到此状态。  
1. 进行 [用户需求对齐] 章节的内容
2. 进行 [了解项目] 章节的内容
3. 跟用户多轮对话，进行多次步骤 1-2
4. 当用户口头同意后切换到 需求共识 状态

##### 需求共识
1. 在 锚点文件 对应的需求的[描述]章节写入/更新为当前共识内容
2. 切换到 架构研究

##### 架构研究
1. 根据用户需求 提取关键词，启动 subagent 联网搜索
- 搜索不限于文档，别人的实现，其他项目
- 抽象其他人的设计模式
2. 搜索完成后展示给用户
3. 继续跟用户讨论，如果用户修改了需求，按照 [新需求] 的步骤跟用户达成共识，更新锚点文件之后判断相应更新
4. 用户显式确认架构后，进入 架构共识

##### 架构共识
1. 在 锚点文件 对应的需求的[架构]章节写入/更新为当前共识内容
2. 等待用户提出新的需求后，进入 新需求

### 锚点文件
docs/arch 中的一个 markdown 文件
格式为:

```markdown
# 需求 [需求名字/标题]

## 描述

## 架构
```

## Instructions

1. 初始留档
- 简单抽象用户需求到一个短的英文标题
- 在 docs/arch 中以这个标题创建一个 markdown 文件
- 这个文件即为 锚点文件
2. 进入 用户状态机 的 状态切换 循环

### 用户需求对齐

1. 换一种方式(Paraphrase) 复述用户需求
2. 给出具体例子

### 了解项目

1. 阅读项目 ADR 文档记录 (docs/adr)

## 示例工作流
用户: 我想为 xxx 协议写一个协议库，然后针对协议内容写一个状态机
Assistan: 这个状态机能负责什么?
...多轮对话...
Assistan: 这个协议库能实现a,b,c... 这个状态机负责的内容是x,y,z有n个状态切换逻辑是q,p,y...
